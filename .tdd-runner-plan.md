## 4. Open Questions or Assumptions

1. **Test Environment Constraints**: The E2E tests may require a pre-configured dashboard with widgets. If the test environment lacks this setup, the outer boundary may need to shift to controller/service unit tests.

2. **Filter Control Types**: Assumption that Owner/Date Range/Stage map to existing dropdown/select components in the codebase (following `ChartFiltersSettings` pattern). If custom controls are needed, scope may expand.

3. **API Persistence Stub**: Per story description, this story stubs the API persistence layer. The filter state is held in Jotai atoms (client-side only). URL sync and server persistence are handled in dependent stories (STORY-020, STORY-021).

4. **Query Variable Shape**: Assumption that dashboard filters will be passed via existing `filter`/`filterGroup` query variable structure already used by chart-data endpoints, maintaining backward compatibility.

5. **Widget Filter Precedence**: When dashboard filters conflict with widget-local filters, this story applies simple AND logic. Full precedence conflict resolution (dashboard overrides widget) is in scope of STORY-015.
