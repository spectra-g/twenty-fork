# Implementation Plan: STORY-012 (SCRUM-591)

## Story Summary
Establish the foundational dashboard structure by creating the DashboardModule, resolver, and service stubs. This sets up the GraphQL boundary for dashboard operations with stubbed responses.

## Files to Create or Modify

| File Path | Action | Purpose |
|-----------|--------|---------|

| `packages/twenty-server/src/modules/dashboard/services/dashboard.service.ts` | CREATE | Service stub with placeholder methods |

## Acceptance Test Anchors

| AC-ID | Outer Test Description | File |
|-------|----------------------|------|
| AC-001 | GraphQL resolver methods are reachable (stubbed responses) | `dashboard.resolver.spec.ts` or E2E if available |
| AC-002 | DashboardModule imports without circular dependency errors | `dashboard.module.spec.ts` |

## Implementation Order (Outside-In TDD — Double Loop)

**AC-001: Resolver methods reachable**

1. **Outer loop** - Write failing test at controller/resolver boundary:
   - Create `dashboard.resolver.spec.ts` that instantiates `DashboardResolver` and calls stub methods
   - Run: `mise exec -- yarn test packages/twenty-server/src/modules/dashboard/resolvers/dashboard.resolver.spec.ts`
   - Confirm FAILS (module/resolver doesn't exist)

2. **Inner loop 1** - Module creation:
   - Write failing test for `dashboard.module.ts` to verify it compiles and exports providers
   - Create `dashboard.module.ts` with basic `@Module()` decorator
   - Run module test → GREEN

3. **Inner loop 2** - Resolver stub:
   - Write failing test for `dashboard.resolver.ts` to verify resolver class exists
   - Create `dashboard.resolver.ts` with `@Resolver()` and stub `@Query()` methods
   - Run resolver test → GREEN

4. **Inner loop 3** - Service stub:
   - Write failing test for `dashboard.service.ts`
   - Create `dashboard.service.ts` with `@Injectable()` and stub methods
   - Run service test → GREEN

5. **Outer loop verification**:
   - Re-run resolver tests with module integration
   - Confirm stub methods return expected placeholder values

**AC-002: No circular dependencies**

1. **Outer loop** - Write failing test:
   - Create `dashboard.module.spec.ts` that imports DashboardModule and verifies no circular deps
   - Run: `mise exec -- yarn test packages/twenty-server/src/modules/dashboard/dashboard.module.spec.ts`
   - Confirm FAILS (module doesn't exist)

2. **Inner loop** - Verify module structure:
   - Ensure DashboardModule imports/exports are clean
   - Run module test → GREEN

3. **Final verification**:
   - Import DashboardModule in a test app module to verify integration
